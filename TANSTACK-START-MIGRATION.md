# TanStack Start migration recipe for Cloudflare seeds

This recipe preserves existing applications while changing their rendering stack.
Author common runtime changes in the base repository, shared domain and modules
in the family repository, and finished screens in edition sources. Assemble and
verify the full edition repository. Existing paths below locate migration work
inside an application; map each change back to its canonical author source.
Owners may instead migrate their own fork directly and edit any source.

Status: accepted implementation-backed recipe for the default seed reference at proof commit `3889e8a0ae0424913402892e0d5592eb9102a034`, which includes implementation commit `c5c661f5984525cec8f1b06a6309917992fd97ea`. The author, root reviewer, and an independent detached-clone reviewer passed `pnpm install --frozen-lockfile && pnpm verify`. The proof includes changed-D1 SSR, explicit prerendering, Hono/Start dispatch and auth, Queue/Cron effects, true 404s, client-bundle boundaries, browser error capture, and authenticated client navigation. No production deployment was performed.

This migration changes the document renderer while keeping one Cloudflare Worker and the existing TypeScript domain and backend. TanStack Start owns selected React document routes and its generated server-function transport. Hono continues to own the existing API, native auth, health, webhook, and product-specific HTTP routes. Existing `queue`, `scheduled`, `email`, Durable Object, Workflow, and other module exports remain on the custom Worker entry.

## 1. Freeze the existing behavior

Start from an accepted seed commit and record it. Run the seed's complete verification before changing dependencies.

```sh
git rev-parse HEAD
pnpm verify
```

Write a request ownership table from the actual Worker, Wrangler config, `seed.json`, and contract tests. Include methods, exact paths and prefixes, required host, authentication, Origin/CORS rule, response type, and handler. Classify every entry as one of:

| Owner | Requests |
|---|---|
| Hono | API namespaces, health, native auth and callbacks, inbound email/webhooks, authoritative public artifacts, feeds, widgets, and any raw HTTP response whose contract already exists |
| Start | Chosen React document routes and `/_serverFn/<generated-id>` |
| Assets | Built JS/CSS and explicitly prerendered HTML generated by the Vite build |
| Worker events | `queue`, `scheduled`, `email`, Durable Object, Workflow, and named exports |
| 404 | A request that reaches route matching after its declared host, method, Origin, authentication, and other guards, but matches no surface |

Match `/` by equality. For every namespace, decide whether its base path is owned too: `/api` and `/api/*` should normally reach the same Hono application. Do not use a Hono catch-all to discover whether Hono matched; that can consume Start documents or its transport.

Preserve guard ordering as part of ownership. A protected namespace can authenticate before route matching: an anonymous unknown member keeps its native-auth response, while an authenticated request that satisfies its normal preflight can reach the Hono 404. Do not make a protected path public merely to exercise a 404.

Preserve owner customisations and local intent tests wherever they live. Upstream releases leave `src/ext/`, `.seed/`, `migrations/ext/` and `tests/local/` untouched after installation; owners may edit core too. The rendering migration preserves domain behaviour, data, released migrations and supported extension contracts. Never regenerate over an owner fork.

## 2. Install Start and configure the builds

Add the proven versions with exact pins. Keep the seed's existing UI packages and Cloudflare bindings.

```sh
pnpm add --save-exact @tanstack/react-start@1.168.50 @tanstack/react-router@1.170.33
pnpm add --save-dev --save-exact @cloudflare/vite-plugin@1.54.5 @vitejs/plugin-react@6.1.1 vite@8.2.2 wrangler@4.129.1
```

Use the Cloudflare, Start, and React plugins in this relative order. Existing plugins such as Tailwind may follow them and must be verified in the migrated build.

```ts
export default defineConfig({
  plugins: [
    cloudflare({ viteEnvironment: { name: 'ssr' } }),
    tanstackStart({
      prerender: {
        enabled: true,
        autoStaticPathsDiscovery: false,
        crawlLinks: false,
        failOnError: true,
      },
      pages: [
        {
          path: '/reference',
          prerender: { enabled: true, outputPath: '/reference/index.html' },
        },
      ],
    }),
    react(),
  ],
})
```

Replace `/reference` with the seed's genuinely deployment-invariant page or remove `pages` and disable prerendering. A page backed by live D1 or R2 data, authentication, tenant configuration, a secret, or current time is not invariant. Cloudflare prerendering runs at build time against build-time variables and binding data; it does not read the later deployment's live state. Disable automatic discovery and link crawling so a public link cannot accidentally prerender `/signin`, `/app`, or a dynamic public record. In the reference artifact, `/reference` redirects to the generated canonical `/reference/`, which returns the meaningful prerendered HTML; choose and test each seed's trailing-slash contract explicitly.

Point the input Wrangler config at the custom entry, set `nodejs_compat`, and preserve all D1, R2, Queue, email, service, and other bindings and migration directories:

```jsonc
{
  "main": "src/server.ts",
  "compatibility_date": "2026-09-08",
  "compatibility_flags": ["nodejs_compat"]
}
```

Remove `assets.not_found_handling = "single-page-application"`. It is the old HTML fallback and hides unknown routes. With the Cloudflare Vite plugin, omit `assets.directory`; `vite build` generates `dist/client`, `dist/server/wrangler.json`, and `.wrangler/deploy/config.json`, and the generated config points at the client output. Ignore `dist/`, `.wrangler/`, `.tanstack/`, `.dev.vars*`, and the package manager's install directory.

For this single-Worker full-stack shape, leave `assets.not_found_handling` unset and implement a Start root `notFoundComponent`. `404-page` has a material Cloudflare routing side effect: with a Worker and a compatibility date on or after 1 April 2025, browser navigation requests can bypass the Worker unless `assets.run_worker_first` or `assets_navigation_has_no_effect` is configured. Use `404-page` only for a seed that needs nearest static `404.html`, after proving every protected and SSR document with `Sec-Fetch-Mode: navigate`.

## 3. Convert the route tree without rewriting the UI

Create `src/router.tsx` with a factory. A new router instance is required for each server request.

```ts
import { createRouter } from '@tanstack/react-router'
import { routeTree } from './routeTree.gen'

export function getRouter() {
  return createRouter({ routeTree, scrollRestoration: true })
}
```

Move programmatic route declarations into Start's file routes and keep importing the existing page and shell components from `src/core/features/**/ui`. Typical mappings are:

| Existing route | File route |
|---|---|
| root layout | `src/routes/__root.tsx` |
| `/` | `src/routes/index.tsx` |
| `/signin` | `src/routes/signin.tsx` |
| `/app` shell | `src/routes/app.tsx` |
| `/app` index | `src/routes/app.index.tsx` |
| `/app/tickets` | `src/routes/app.tickets.tsx` |
| `/app/tickets/$ticketRef` | `src/routes/app.tickets.$ticketRef.tsx` |

The root route must render the complete document with `<html>`, `<head><HeadContent /></head>`, the nested `<Outlet />`, and `<Scripts />` before `</body>`. Put the default title, description, viewport, charset, stylesheet links, and a real `notFoundComponent` there. Add route-specific `head` metadata where public pages need distinct search or sharing text.

Run a build to generate `src/routeTree.gen.ts`; never edit it by hand. Keep it in source control so typecheck and fresh installs see the same route contract.

After the Start document and hydration work, delete the old `createRoot(...).render(<RouterProvider ...>)` entry and the SPA `index.html`. Start supplies the default hydration entry. If a seed needs a custom client entry, it must use `hydrateRoot(document, <StartClient />)`, not `createRoot` on an empty element. Move the global CSS import to the Start route graph.

### Preserve a client-only buyer extension mount

Keep `src/ext/index.client.tsx` buyer-owned and out of the SSR graph. When a buyer client contribution must appear only after hydration, initialize the provider with the same empty slot map on the server and the first client render, then load the mount in an effect. Lamp's accepted shape is `createIsomorphicFn().client(async () => (await import("../../../ext/index.client")).lampClientSlots)`; adapt each seed's existing mount path and export, and return the slot map rather than the module object. Surface a missing or rejected mount as an error; do not add an import-protection bypass, server import, or a permanent test fixture. The provider's initial operator context comes from the server-checked route loader, not a client-created session.

## 4. Put data on the correct execution side

Route loaders are isomorphic: they run on the server for an initial SSR request and in the browser during client navigation. Do not access `cloudflare:workers`, D1, R2, secrets, or session storage directly in a route loader.

Keep client-importable server-function wrappers in a normally named file such as `src/core/app/loaders.ts`. In the proven Start 1.168.50 build, naming that wrapper `loaders.server.ts` caused `tanstack-start-core:import-protection` to reject the route's client graph. The working form statically imports the wrapper from the route and dynamically imports true server modules only inside the handler:

```ts
export const loadPublicRecord = createServerFn({ method: 'GET' }).handler(async () => {
  const [{ readPublicRecord }, { requestBindings }] = await Promise.all([
    import('../features/public-record/service'),
    import('../platform/bindings.server'),
  ])
  return readPublicRecord(requestBindings())
})

export const Route = createFileRoute('/')({
  loader: () => loadPublicRecord(),
  component: PublicPage,
})
```

The built client must contain an RPC stub and no `cloudflare:workers`, Drizzle repository, session implementation, or secret. This handler-internal dynamic import is different from dynamically importing the server-function wrapper, which TanStack advises against.

For a Start-owned public document that needs fresh first-response data, move it out of `useEffect` fetch hooks and into a route loader backed by a server function. Leaving the fetch in `useEffect` produces server HTML containing only the loading state. Do not move a contract-owned Hono/R2 snapshot response into a Start loader. Operator-only client fetches may remain when first-response content is not required, but their loading and error behavior must still pass existing tests.

Treat Start's generated transport as a protected application surface. The pinned build emits `/_serverFn/<generated-id>`; the ID is generated and is not an authorization control. Leave the whole `/_serverFn/` namespace with Start. Every protected server function must validate the native session inside its handler before its first private D1/R2 read or mutation, even if `/app` has a parent `beforeLoad` gate. A child data function must repeat the check because its transport request is outside `/app`.

Start installs same-origin CSRF middleware for server functions when there is no custom `src/start.ts`. If a seed adds `src/start.ts`, explicitly retain `createCsrfMiddleware({ filter: (ctx) => ctx.handlerType === 'serverFn' })`. Validate all inputs and use `POST` for mutations. Preserve Hono's existing Origin/CORS checks for Hono mutations, public APIs, auth callbacks, and webhooks. External or cross-origin callers continue to use the existing Hono endpoints; Start server functions are same-origin application RPCs.

### Probe parameterized generated GETs through the pinned wire protocol

For a direct, parameterized generated-GET probe, derive the current `/_serverFn/<generated-id>` from the emitted artifact. Send its payload through the installed seed's generated client request path, or through a local probe that has first round-tripped the exact same pinned wire encoding: the wrapper containing `data` and any nonempty `context`, configured Seroval plugins and async serialization, then the pinned Router query encoder. A hand-built `JSON.stringify({ data })` query is not that protocol. Do not copy or import private Start internals to make a test helper; keep the probe coupled to the seed's installed public client and package graph, and refresh the round-trip proof when those versions change.

Use an otherwise-admissible, same-origin request. Before interpreting authentication, rate, or D1 effects, retain the redacted raw status, headers, and body plus bounded relevant D1 rows from immediately before and after the request, then run a positive control that proves the same wire path reaches the intended handler. A Seroval or transport parse failure establishes only that the application server-function handler was not shown to admit the request; it is distinct from application input validation or middleware failure. Do not infer that every global guard was bypassed, or interpret an unchanged rate row as an authorization or rate-policy result, from a parse failure.

### Adopt the shared session clause

`BASE-ACCESS-002` distinguishes transport semantics without weakening the session check: a valid session is required before private product data or a requested action; a protected document and each private generated server-function handler validate it independently, so a document gate does not authorize a function call. For an otherwise-admissible request that reaches session validation, a protected operator HTTP API returns `401` when the session is missing, expired, or revoked; a protected document preserves its native sign-in response; and a private generated server function may return an identifiable framework denial or sign-in redirect, including a `200` serialized redirect. No such denial response may expose private product data or perform the requested mutation. Declared public exceptions remain under `BASE-ACCESS-003`; host, method, Origin/CSRF, input, and runtime guards keep their normal precedence.

[`changes/2026-09-08-base-access-002.json`](changes/2026-09-08-base-access-002.json) is a reusable `contractChanges` fragment, not a release or version. Each consumer imports `export/BASELINE.md` verbatim through its usual upstream update, copies the fragment's full `was`/`now` change into its actual next `RELEASE.json`, supplies that release's own version, date, migrations, and `agentUpdateInstructions`, and marks `breaking: true`: this narrows the earlier literal universal-`401` promise. The release instructions tell the adopting agent to preserve the native document response and actual generated-RPC protocol rather than normalize either to an API `401` or a generic successful `200`, then run and register the matrix under `BASE-ACCESS-002` before reporting that clause satisfied.

## 5. Compose Hono and Start in one Worker

Use a small custom `src/server.ts`. Route known Hono families first and delegate everything else to Start, including `/_serverFn/`. Hono receives the Worker bindings and execution context; Start server functions read bindings through `env` from `cloudflare:workers` inside server-only code.

```ts
import start from '@tanstack/react-start/server-entry'
import { createApi, isHonoRequest } from './core/app/hono'

const api = createApi()

export default {
  fetch(request, bindings, execution) {
    const pathname = new URL(request.url).pathname
    if (isHonoRequest(pathname)) {
      return api.fetch(request, bindings, execution)
    }
    return start.fetch(request)
  },
  queue: existingQueueHandler,
  scheduled: existingScheduledHandler,
  email: existingEmailHandler,
} satisfies ExportedHandler<Bindings>

export { ExistingDurableObject, ExistingWorkflow }
```

`isHonoRequest` is an explicit, reviewed predicate over exact paths and prefixes. It must include every native auth callback, health/API/webhook family, and any product-owned public response. It must not claim `/_serverFn/`, arbitrary documents, or all of `*`. Preserve request bodies, headers, methods, host dispatch, CORS, error formatting, and status codes when forwarding to Hono. Preserve the event implementations and named exports themselves; do not replace them with samples from the Start guide.

When a strict custom Worker dispatcher intercepts app asset requests, add a separate asset branch after host classification and before Hono or Start. Retain or configure a real asset binding such as `ASSETS` while Vite generates the output directory. On the app-owned host, send the declared emitted JS/CSS asset namespace and, only in development, the concrete Vite/Start virtual-module paths observed in that seed's dev session to that binding's `fetch(request)`. The development predicate is an explicit reviewed list, remains subject to the app-host check, and is not a generic file fallback. It is disabled in the emitted production Worker, which exposes only declared routes and generated assets. `/_serverFn/` is not an asset path: leave it with Start and retain its session and CSRF protections.

Preserve a seed's native anonymous operator-document redirect as an explicit preflight before Start. Keep its current route, status, headers, body, and safe `returnTo` semantics: Lamp redirects an unauthenticated `/app` document to `/signin?returnTo=…` with `302`; the reference pilot's `307` is not a universal replacement. This document gate does not authorize generated RPC: each protected `/_serverFn/` handler still rechecks the native session before private work. Do not force that document `302` onto RPC: the reference's anonymous same-origin server-function call returns `200` with a serialized sign-in redirect, so test absence of private payload and side effects alongside protocol status.

Start's default entry streams SSR responses. Return that `Response` directly. Do not call `.text()`, buffer it, or wrap it in a new response unless a contract requires a tested transformation.

## 6. Product-specific ownership

**Lamp:** preserve two-host dispatch before either framework. On its public host, Hono owns the exact `/`, `/history`, `/feed.atom`, `/widget.js`, `/api/public/status`, `/subscribe`, and `/unsubscribe` paths, plus the declared `/incidents/`, `/maintenance/`, `/assets/`, `/manage/`, and `/api/intake/` prefixes and their contract-defined methods. `POST /subscribe` and the other public mutations remain Hono-owned and are tested as mutations. Separately, PAGE-005/PAGE-006 make the rendered public-page HTML, Atom feed, and widget payload authoritative R2 snapshots: serving them issues zero D1 queries and continues through a D1 failure from the current snapshot. Keep the shared incident renderer used by those public artifacts and notification email. Use Start only for `/signin`, the operator `/app` React tree, and its generated server-function transport; do not create a second Start-rendered public status source.

**Lily:** preserve the complete current Hono allowlist, including `/health`, `/api` and `/api/*`, native auth callbacks, email/webhook ingress, and their exact Origin rules. Keep `prepareRuntime`, `enforcePublicRequestBoundary`, and `/api/*` `requireApiSession` in that order: only its exact permitted public rules bypass the native session gate. An anonymous unknown protected API member therefore keeps Lily's `401` JSON response before Hono matches it; the same request with a valid native session and normal method/Origin preflight reaches the Hono 404. Preserve its `email`, `queue`, and `scheduled` exports and the packaged Vite artifact/configured-or-disabled browser profile behavior. Start may render `/`, `/signin`, and the `/app` documents. Gate the first `/app` document with the native session and repeat session checks inside every private server function. Test the generated `/_serverFn/` transport directly with and without cookies and with a hostile Origin.

**Beacon:** preserve `/health`, `/api/v1` and `/api/v1/*`, `/auth` and `/auth/*`, event exports, API loaders, and its native session behavior in Hono. Replace only the current asset-served React documents with Start. Keep private loader checks and explicit Hono/Start/404 seams.

For every seed, a framework does not create missing product routes. A declared help, article, survey, feed, widget, webhook, or public record still needs an implemented owner and a contract test.

## 7. Build, preview, and acceptance

Keep the existing deterministic setup and D1 migration commands. The minimum scripts are `vite dev`, `vite build`, `vite preview`, typecheck, binding type generation, and the seed's full verify. A deploy script may be `pnpm build && wrangler deploy`, but this migration does not authorize a deploy.

The maintained Base default-seed and exported foundation typechecks in `verify` use checkout-local, gitignored `.cache/typecheck.tsbuildinfo` in each package; deleting it forces a full check, while `build` still builds the real Worker and assets.

The Vite plugin treats Wrangler as build-scoped configuration. Choose `CLOUDFLARE_ENV` when running `vite build`; passing `--env` to the later `wrangler deploy` does not change the generated environment. Always build before preview or deployment so Wrangler follows `.wrangler/deploy/config.json` to the current generated configuration.

Before installing, building or cleaning output, validate the actual durable local
state root outside every generated directory. Resolve physical symlink ancestors;
a lexical path outside `dist` can still point into it. Refuse unresolved links or
legacy generated-output state without moving/deleting data. Preserve and explicitly
recover/adopt any old D1/R2 state before rebuilding, verifying row/blob hashes,
sessions and the applied migration ledger. The foundation installer exports
`selectLocalState` for this preflight and defaults to absolute checkout
`.wrangler/state`; editions own equivalent guards for their actual cleanup paths.
Keep Vite `persistState`, local migrations and emitted preview on the same durable
root. Every generated-config local Wrangler command must explicitly pass
`--persist-to "$STATE"`, including `d1 migrations apply DB --local --config
dist/server/wrangler.json --persist-to "$STATE"`. Changing only the command can
strand previous data. Adopt through edition-owned source; never regenerate edited
products. See [foundation onboarding](foundation/template/ONBOARDING.md) for the
read-only selector and explicit command recipe.

Base's bounded regression is `node foundation/verify-export.mjs
--state-safety-only`. It creates a disposable committed export, preserves synthetic
populated D1/R2 row/blob hashes, sessions and migration ledger through two real
installer dependency/build phases and binding-runtime restarts, and checks
symlink/output and legacy refusals before writes or cleanup. It deliberately stops
the installer before child-preview launch and disposes binding runtimes through
their API; this mode excludes browser, preview-process shutdown and deployment
dry-run checks. It does not certify another edition's adoption or recover owner
data.

### Configure Cloudflare Vitest from resolved Start settings

Cloudflare Vitest can serve a Worker through a raw-module fallback: Vite resolves the module, but TanStack Start's Vite `define` replacements may not reach server-core. If a real generated-transport Worker test exposes that boundary, resolve and verify the current pinned Start planner values from that seed's Vite configuration, then write the checked values into an ignored Vitest-only Wrangler config generated from its ordinary local config. The generator may contain verified literals; it is not automatic planner extraction. Select that generated config only from the Vitest configuration; do not change the deployed template, generated production Worker config, or application runtime. This is a test-runtime configuration, not a production fallback.

Do not transplant a fixed list of `TSS_*` values from another seed. Record and check the current resolved server-function base, router base, shell, serve-mode, style, inline-CSS, and CSRF-warning settings. Write the planner's string-literal replacement expressions under Wrangler `[define]`, never `[vars]`, then compare Wrangler/Miniflare's parsed define map with the resolved planner map. Preserve an empty router base when that is the planner value—Start normalizes it to `/`—rather than silently changing it to `/`. Resolve, recheck, and update the ignored test configuration whenever the pinned Start/Vite plugin set or its configuration changes.

Exercise a real transformed server function, deriving its current safe generated ID rather than copying one. Construct the request through its actual GET or mutation protocol: the server-function marker, negotiated `Accept` values, same-origin `Origin` and Fetch Metadata, cookie where needed, and a payload encoded with the pinned transport only when the function accepts one. For a no-input GET whose successful response is Start-serialized JSON, preserve raw status and `Content-Type`, require the actual Start serialization header, and decode through the matching installed Seroval dependency and plugin set. Where the browser/native decoder requires Start AsyncLocalStorage unavailable to the Worker-test harness, decode that raw serialized JSON through the compatible public Seroval protocol instead; do not fabricate browser context or a different transport. A native denial or redirect is a distinct response path: assert its actual protocol rather than forcing that header or decoder. This narrow helper does not prove parameterized input, framing/streams, raw responses, custom serialization adapters, or browser-client RPC.

Workers Vitest evidence can establish the tested Worker path and registered baseline result. It does not replace the emitted-Worker, actual `vite dev` browser, or production-artifact `404` and asset checks below.

The migration is accepted only when all of the following are automated or captured as reproducible local evidence:

### Shared session transport matrix (`BASE-ACCESS-002`)

Use missing, expired, revoked, and valid session controls with otherwise-admissible, valid-host, same-origin requests that satisfy the route's method, input, and runtime prerequisites. Test each private generated server function, each protected document family, and a known plus unknown protected HTTP API route in every protected API namespace.

| Surface | Missing, expired, or revoked session after it reaches session validation | Valid-session control |
|---|---|---|
| Protected operator HTTP API | `401`, with no private product payload or requested mutation | The known route keeps its contract; the unknown route reaches the Hono `404` only after its normal guards pass |
| Protected operator document | Its native sign-in response, with exact status, `Location`, headers, body, safe `returnTo`, and no private HTML | Its contract-defined private document response |
| Private generated server function | Its exact identifiable framework session-denial or sign-in-redirect protocol, which may be a `200` serialized redirect, with no private product payload or requested mutation | Its contract-defined private result or mutation |

Wrong Origin, absent request metadata, malformed input, and runtime failures need their own checks; a resulting `403` or other response is not a session proof. Register each matrix result to `BASE-ACCESS-002` through the seed's actual contract/baseline reporter: a plain, unmapped test does not satisfy the clause, and its status remains to-do or broken until the matrix has run and been reported. Declared public exceptions remain public under `BASE-ACCESS-003`, and public-document, missing-asset, development-path, and unsupported-host `404` checks remain unchanged.

**2026-09-08 scope:** this matrix and reporter registration are new acceptance requirements. This task does not change or claim execution of the shared baseline pack. The earlier `ca3f3b4`/`3889e8a` reference-runtime proof predates this matrix and cannot establish every row or a reported `BASE-ACCESS-002` result. The separately tracked shared-pack lift and each consumer's registered tests must execute the new requirement.

### Full migration checks

1. Fresh install, binding type generation, existing D1 migrations, typecheck, seed tests, `vite build`, and the full `pnpm verify` pass. Where a custom Worker dispatches development assets, run a browser against `vite dev` and prove the actual Vite/Start scripts and styles load, React hydrates, expected route content is present, and there are no failed requests, browser errors, or layout failures.
2. The build emits only the explicitly allowed prerender pages. Their HTML contains real body content, metadata, hydration scripts, and no private or environment-dependent data.
3. Start the emitted production artifact in `workerd` after `vite build`, using `wrangler dev --config dist/server/wrangler.json --local --persist-to "$STATE" ...`. For every Start-owned dynamic document declared to render fresh bound data, a direct request contains that current data in the first HTML response; changing the relevant local binding and requesting again changes the HTML. This proves request-time SSR only for those declared Start documents, not for an allowed invariant prerender or a Hono/R2 snapshot surface.
4. Within the hydrated React application, links between Start-owned React documents and an authenticated link into the operator app navigate client-side: one initial document request, a stable `performance.timeOrigin`, no failed route or server-function request, and no browser `pageerror` or hydration error in the console. Check sign-in links when the seed exposes them in this flow. A deliberate boundary from a React document to a Hono-owned public snapshot is a document navigation and must preserve that raw snapshot response; it is not an SPA-navigation failure.
5. Execute the shared session transport matrix. An unauthenticated `/app` document preserves the seed's native sign-in redirect status, headers, body, and safe `returnTo` semantics; do not substitute the reference pilot's `307` for a seed such as Lamp whose contract uses `302`. An authenticated request renders private data, and authenticated browser navigation into `/app` successfully exercises the protected server-function transport without a new document. Cross-origin mutation transports receive `403`; authorized same-origin mutations still work, but that Origin result is separate from session proof. For a parameterized direct generated-GET probe, derive the emitted ID, use the pinned generated-client encoder and configured serializers, retain raw response evidence and bounded before/after D1 rows, and require a same-wire positive control before treating a response or row delta as handler, authentication, or rate behavior. A protocol parse failure is not an application-admission result. If Cloudflare Vitest supplies this proof, keep its resolved Start settings and real request/response protocol evidence with the registered result; it does not replace the emitted-Worker and browser checks.
6. Every Hono-owned path retains its method, host, Origin/CORS, auth, status, response body/type, and observable side effects. Test Hono-owned mutations separately from read paths. For an authoritative Hono/R2 snapshot surface, test that its contract-defined publication or update writes the next snapshot, then inspect raw responses for meaningful HTML and document metadata or the required feed/widget payload, correct status, type, and cache policy, and the contract-required shared public/email rendering. Assert zero D1 queries while serving the snapshot and that a forced D1 failure still serves the current snapshot when its contract requires it. A protected Hono namespace can authenticate before matching: for a representative unknown member, assert its anonymous native-auth response and, with a valid native session and normal method/Origin preflight, the Hono 404. Preserve each response's status, headers, and body; do not make a protected member public to obtain a 404. Hono dispatch can be distinguished in the test without changing production response contracts, for example through a test-only trace or a stable existing header.
7. Queue, scheduled, email, webhook, and named-export behavior is invoked against local real bindings and produces its expected state change. Test handlers directly only where `workerd` has no equivalent trigger.
8. Against the emitted production Worker, an unknown public document, missing built asset, representative development-only Vite/Start virtual path from the observed dev request log, and unsupported host each return a real `404`; none returns the app shell with `200`. For an unknown protected document or Hono/API path, satisfy its native authentication and normal preflight before asserting the real `404`; an anonymous protected request instead retains its native-auth response. Also prove a declared emitted app asset is served with its expected type. Repeat document checks with `Sec-Fetch-Mode: navigate` to catch Cloudflare asset-routing differences.
9. The browser bundle contains no `cloudflare:workers`, Drizzle repository, session implementation, owner credential, or other server-only module. Existing core/ext import-boundary checks remain green.
10. Where the seed has a client extension mount, prove it in an isolated checkout with a temporary nonempty buyer `index.client` contribution. The raw authenticated SSR response contains the server identity but not the extension marker; the initial client tree matches that SSR, then the browser renders and interacts with the contribution after hydration. An internal React link remains in one document with stable `performance.timeOrigin`, and failed requests, page errors, and console errors are empty. Scan emitted server JavaScript to prove it contains neither the buyer client-mount import nor the extension marker; remove the temporary fixture after the proof.

Run `vite dev` for iteration. The reference's proven production-artifact check runs the generated `dist/server/wrangler.json` through local `wrangler dev` after every build. Also run `vite preview` as Cloudflare's recommended pre-deploy smoke test; it uses the generated build output, but it was not the command exercised by this reference verifier. Browser-only Vite success is insufficient.

## Known limits and update triggers

- TanStack's current official overview still labels Start a release candidate: feature-complete with an API considered stable, but not bug-free. Upgrade one pinned package set at a time and rerun this whole matrix.
- Cloudflare documents Start, its Vite plugin, bindings, custom event entrypoints, and prerendering. The exact Hono-first dispatcher is a composition of their Fetch-compatible entries and is proven by this repository, not supplied as a complete official template.
- Local `workerd` preview is the closest local production check, but this work did not deploy. Remote hosts, production secrets, D1/R2 contents, email routing, Queues, Cron Triggers, caches, and Cloudflare asset routing still require a staging smoke test before release.
- Prerendering can access build-time local or remote bindings. Keep the allowlist deployment-invariant unless the release process deliberately supplies and audits remote production data.
- The Vite build output and generated Wrangler config are build artifacts. Never edit them, commit them, or treat their hashed server-function IDs as stable API paths.
- A Start upgrade can change import protection, transport internals, generated outputs, or plugin integration. Inspect the built transport and client bundle again instead of copying old hashes or output paths.
