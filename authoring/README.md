# Publish remaining legacy canonical editions

The Base publisher serves Support family authoring CI for Beacon, Brook and
HappyToHelp. Lily, Orbit, Lamp and Ferry use edition-owned authoring and must not be
regenerated by this publisher. It updates complete generated
upstream repositories; it must never be used to update an owner's fork.
The helper remains reusable, but Sales has no current legacy publication targets.

Commit `publication.json` beside the family's `family.json`:

```json
{
  "schemaVersion": 1,
  "family": "runeditrun/support",
  "editions": {
    "beacon": "runeditrun/support-beacon"
  }
}
```

Each edition has an explicit, unique destination in the family repository's
owner namespace. Names are not inferred. Support records Beacon, Brook and
HappyToHelp as explicit mapping entries.
The publisher reads both descriptors from the supplied family commit, never from
uncommitted files. Origin and any push URL must match those declared identities.

After committing Base, pin that commit in the family, commit the family changes,
and merge them to family `main`. CI checks out the exact pinned Base, exports
and verifies each edition, then invokes:

```sh
node base/authoring/publish.mjs --source source-beacon --target upstream-beacon \
  --family support --sha "$GITHUB_SHA" --edition beacon --check
node base/authoring/publish.mjs --source source-beacon --target upstream-beacon \
  --family support --sha "$GITHUB_SHA" --edition beacon
```

`--check` performs read-only preflight. The source lock must identify the selected
edition, exact current family-main commit, and its pinned Base. Its complete
file inventory, hashes and executable bits must match. The target must be clean,
including ignored untracked files, and at current upstream main. Existing target
bytes must still match their prior composition lock, and the previous family
revision must be an ancestor of the new revision. Changed source is committed
on top of existing target history. Identical output is a no-op. Family and target
main are rechecked immediately before an ordinary non-forced push; Git rejects
non-fast-forward target races. No deployment or external message is performed.

A newly created empty canonical repository is supported: clone it to an empty
target checkout with its canonical origin before invoking the helper. Bootstrap
uses the same mapping, provenance, current-family-main and tree checks. CI must
not publish an unmerged family SHA. Existing generated repositories should be
checked out with their main branch; full family history is needed for ancestry.
Do not seed new repositories with a README before generated publication.

The workflow remains responsible for credentials, build/behavior checks, and
per-family publication concurrency. Run `pnpm verify:authoring` for real local
Git remote tests covering both families, initial publication, history, drift,
fork boundaries, committed mapping authority, stale source and target races.
These tests certify publisher mechanics, not the product contracts or a hosted
publication. Owner updates remain ordinary Git integration with intent checks.
